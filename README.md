# FC 온라인 매물 분석 도구

## 구성
| 경로 | 내용 |
|---|---|
| `config/settings.json` | 모든 기준값 (수수료 20%, 가격대 프리셋, 운용 BP, 수집 범위) |
| `config/secrets.local.json` | NEXON Open API 키 (공유·커밋 금지) |
| `data/fco.sqlite3` | 수집 데이터 (랭킹 스냅샷, 스쿼드, 카드 마스터, 호출 기록) |
| `fco/` | 수집·분석 코드 (Python 3.12 표준 라이브러리만 사용) |
| `01_데이터_수집_가능성_분석.md` | 1단계 보고서 |

## 가격대 변경
`config/settings.json` → `priceRange.activePreset` 을 `"1억-10억"` 또는 `"10억-100억"` 으로 바꾼다.
새 구간이 필요하면 `presets` 에 `{ "minBp": ..., "maxBp": ... }` 를 추가한다.
카드 후보군(랭커 스쿼드)은 가격과 무관하게 수집되므로, 프리셋을 바꿔도 다시 수집할 필요가 없다.

## 바탕화면에서 열기
바탕화면의 **FC 매물 분석** 바로가기를 더블클릭 → 대시보드 서버가 꺼져 있으면 창 없이 켜고 브라우저로 연다.
서버는 브라우저를 닫아도 계속 돈다 (컴퓨터를 끄거나 다시 켜면 꺼지고, 바로가기로 다시 켜면 된다).
바로가기를 다시 만들려면: `powershell -ExecutionPolicy Bypass -File scripts\create_shortcut.ps1` (폴더를 옮긴 뒤에도 실행)

## 내 기록 백업 · 복원
보유 매물 · 매도 기록 · 쿠폰을 추가/수정/삭제할 때마다, 그리고 서버를 켤 때마다 `data\backups\user_records_<시각>.json` 이 저장된다 (최근 100개).
```powershell
& $py -m fco.backup list                                   # 최근 백업 목록
& $py -m fco.backup restore data\backups\user_records_....json   # 그 파일에 있고 지금 없는 기록만 다시 넣기
```

## 수수료 · 쿠폰
- 판매 수수료 = 기본 40% × (1 − PC방 30% − TOP CLASS 20% − 쿠폰). 할인은 더해서 적용, 0 밑으로는 안 내려감 (FC STATS 수수료 계산기 안내 기준, 이벤트로 바뀔 수 있어 설정에서 변경).
- 쿠폰 1장 절약 = 판매가 × 40% × min(쿠폰, 남은 할인 여지). 판매가에 비례 → 큰 쿠폰은 비싼 판매에.
- 대시보드 '수수료 쿠폰': 보유 쿠폰 입력 → 보유 매물 매도 + (지금 살 수 있는) 신규 매수 후보까지 판매 1장 단위로 펼쳐 배정. 쿠폰 등급별로 '쿠폰이 있어야 수익이 나는 카드' 목록.

## 상한가 · 하한가 (fionhub)
- 넥슨 데이터센터에는 상한가·하한가가 없어 fionhub.com 선수 페이지 데이터(`/player/<id>/<강화>/x/__data.json`)를 읽는다. robots.txt 허용 확인, 1초에 1번, 차단 페이지가 나오면 우회 없이 건너뜀.
- 받는 값: fionhub 현재가, 하한가, 상한가, 구매·판매 대기 호가, 최근 2시간 거래 건수 → `market_snapshot` 에 갱신마다 쌓임. fionhub 카드 ID 는 `fionhub_card` 에 저장.
- 언제: 빠른·전체 갱신 때 보유 매물 + Deal Score 상위 `market.topN`(30)장. 대시보드 '상한가 지금 확인' 버튼은 보유 매물만 바로.
- 계산: 상한가 매도 손익 = 수량 × (상한가 × (1 − 수수료) − 매수가). 쿠폰 열은 보유 중 가장 큰 쿠폰 기준. '상한가 구매 대기 N건' 이 있으면 상한가에 바로 팔린다는 뜻.
- 하한가 매수 → 같은 시세의 상한가 매도: 상한가 ≈ 하한가 × 1.22 라 수수료 20% 면 약 −2%, 100% 쿠폰이면 약 +22%. 쿠폰 없이 수익을 내려면 시세 자체가 올라야 한다.
- `python -m fco.fionhub` (보유 매물) / `python -m fco.fionhub --watch` (갱신 대상 전체)

## 랭커 픽 추천 (사용자 기준, 대시보드 '랭커 픽 추천')
- 출처: fc-info.com/ranker-pick/official (공식경기 랭커가 선발로 쓴 카드, 팀컬러별·포지션별 픽률, 하루 1번 갱신). robots.txt 허용 확인, 1초에 1번.
- 후보: 인기 팀컬러 `topTeams`(20)위 안 팀의 포지션별 `topRankPerPosition`(10)위 카드와 같은 시즌(spid) · 랭커가 쓴 강화 중 `minGrade`(8)강 이상이고 `minGradePicks`(3)명 이상 쓴 것.
- 조건: 현재가(fionhub, 없으면 데이터센터) < 지난 토·일 일별 가격 평균 · fionhub 2시간 거래 ≥ `minTransfers2h`(5)건 · 활성 가격대 안.
- 점수 = 거래량 40 × log(1+거래)/log(1+최대) + 픽률 35 × 최고 픽률/최대 + 하락 25 × 하락률/최대 (같은 카드가 여러 팀·포지션이면 가장 높은 픽률).
- 받는 팀컬러: fionhub 카드 정보 (소속·국가 / 특성 / 강화). 인기 20위 팀컬러는 초록색 + 순위.
- 갱신: 전체 갱신(daily) = fc-info 표 + 후보 데이터센터 가격(20시간 지난 것) + fionhub. 빠른 갱신(quick) = 가격대 안·주말보다 싼 후보의 fionhub 거래량만 (`maxMarketFetch` 120장, 픽률 높은 순).
- `python -m fco.rankerpick prices` (전체) / `quick` / `show`

## 로그인 · 휴대폰(외부) 접속
- 대시보드는 비밀번호 로그인 필요 (`fco/auth.py`). 비밀번호는 PBKDF2 해시만 `config/secrets.local.json` 에 저장. 로그인 30일 유지.
  같은 접속지 5번 틀리면 15분, 전체 1시간 20번 틀리면 1시간 잠금. 바꾸기: `python -m fco.auth set` / 모든 기기 로그아웃: `python -m fco.auth logout-all`
- 외부 접속: Cloudflare 임시 터널 (`fco/tunnel.py`, `tools/cloudflared.exe` = Cloudflare 공식 GitHub 2026.11.0, SHA256·서명 확인).
  서버는 계속 127.0.0.1 에만 열리고 터널이 https 로 연결. 공유기 포트 안 엶. 주소(`https://….trycloudflare.com`)는 터널을 다시 열 때마다 바뀜.
- 지금 주소: 대시보드 3탭 '외부 접속', 바탕화면 `FC 매물 분석 외부 주소.txt`, `data/tunnel.json`.
- 자동 시작: 작업 스케줄러 'FCO 외부 접속' (로그인 시, `scripts/register_tunnel.ps1`). 끄기: `Unregister-ScheduledTask -TaskName 'FCO 외부 접속' -Confirm:$false` 후 pythonw(fco.tunnel)·cloudflared 종료.
- PC가 켜져 있어야 하고 절전 모드면 끊김.
- 카카오톡 알림 (`fco/kakao.py`): 새 외부 주소가 생기면 카카오 공식 API '나에게 보내기'로 나와의 채팅에 전송 (기본: PC 카카오톡 실행 중일 때만, 최대 5분 기다림).
  설정은 대시보드 3탭 '카카오톡 알림' (카카오 개발자 앱 · REST API 키 · Redirect URI `http://localhost:8765/kakao/callback` · 동의항목 talk_message). 키·토큰은 `config/secrets.local.json` 의 "kakao". 결과는 `data/tunnel.log` 의 `[kakao]` 줄.

## 탭3 고가 선수 장기투자 (`fco/longterm.py`, 설정 `longTerm`)
- 대상: 데이터센터 현재가 10억 이상 + 일별 가격 있는 카드. 인기 순위 = fc-info 인기 팀컬러 20위 팀의 포지션 순위 중 최고 (15위까지만 공개).
- 상승 추세형(Momentum)과 저평가 선점형(Value)은 독립 점수 · 독립 순위 (같은 카드가 양쪽에 나올 수 있음). 항목별 비율 × 배점, 데이터 없는 항목은 빼고 100점 환산.
- 매수 후보 = 점수 75↑ + 인기 20위 이내 + 위험 없음 + 현재가 ≤ 매수 적정가 × 1.02. 보유 중인 10억+ 카드는 매도 검토 신호 표시.
- 거래량: 갱신 때 두 순위표 상위 30장씩 fionhub 2시간 거래 · 매물 (받은 카드만 점수에 반영). `/api/longterm`.
- 탭 순서: 1 보유·랭커 픽 / 2 검색·자금 배분 / 3 장기투자 / 4 검증·갱신 기록·설정 (모바일 하단 탭 4개).
- 탭3 맨 아래 '거래 많은 순 TOP 15' (`longterm.trade_top`): 게임 '최다 조회수'는 공개되지 않아 fionhub 2시간 거래 건수로 대신. 최근 3시간 안에 받은 값만, 10억 이상 / 전체 가격대.

## 모바일 화면 (같은 주소, 767px 이하에서 자동)
- `fco/static/index.html` 안의 `#mobile` 영역 + `html.m` 스타일. PC 화면(헤더 · 3탭)은 그대로이고 좁은 화면에서만 숨김. 768~1023px 은 PC 화면에 칸 배치만 조정.
- 하단 탭: ① 보유 현황(요약 · 보유 카드 펼침 · 정렬) ② 검색·매수(선수명 · 시즌 · 강화 · 가격대 필터, ★ 관심 매물, 검색어 없으면 랭커 픽 추천) ③ 매매 분석(누적 요약 · 일/주/월/전체 · 누적 실현 손익 그래프 · 거래 내역 · 추천 검증 · 외부 접속).
- 판단 (`fco/judge.py`, 기존 식 조합): 매수 = 랭커 픽 추천 조건 충족 + 현재가 ≤ 적정 매수가(지난 주말 평균 × (1−수수료) ÷ 1.05, 안 되면 쿠폰 수수료로) / 매도 = 상한가 ≥ 목표 매도가(매수가 × 1.05 ÷ (1−수수료), 쿠폰 있으면 쿠폰 수수료로) / 그 밖은 관망 + 이유.
- 관심 매물은 `watch` 표 (자동 백업 포함). API: `/api/m/search`, `/api/m/seasons`, `POST /api/watch`.
- 'PC 화면으로 보기'(모바일 ③) ↔ '모바일 화면'(좁은 화면의 PC 헤더) 로 그 기기에서 바꿀 수 있음.

## 실행 (PowerShell)
```powershell
$py = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python312\python.exe'; $env:PYTHONIOENCODING='utf-8'
& $py -m fco.collect_squads            # 랭킹 1~200위 스냅샷 + 스쿼드 + 카드 매칭 (API 약 600건)
& $py -m fco.collect_squads --resume   # 일일 한도로 중단된 스냅샷 이어서 수집
& $py -m fco.collect_prices            # 카드별 현재가 + 365일 일별 가격 + OVR (1초 1건, 전체 약 1시간)
& $py -m fco.collect_prices --only-top20   # 1~20위 스쿼드 카드만 (약 5분)
& $py -m fco.price_report              # 수집 현황 + 활성 가격대 카드
& $py -m fco.price_report --preset 10억-100억   # 다른 가격대 미리보기
& $py -m fco.analyze_weekly            # 4단계 평일·주말 분석 (weekly_stats 저장 + 요약)
& $py -m fco.collect_squads --top 20   # 1~20위 스쿼드만 새로 받기 (API 약 40건)
& $py -m fco.analyze_popularity        # 5단계 인기 스쿼드 점수 (popularity_stats 저장 + 요약)
& $py -m fco.analyze_stability         # 6단계 가격 안정성 (stability_stats 저장 + 요약)
& $py -m fco.analyze_pricing           # 7단계 매수 적정가·수익률 (pricing_stats 저장 + 요약)
& $py -m fco.analyze_deal              # 8단계 Deal Score TOP 20 (deal_stats 저장)
& $py -m fco.analyze_deal --buyable    # '지금 매수 가능' 카드만
& $py -m fco.dashboard                 # 9단계 대시보드 → 브라우저에서 http://127.0.0.1:8765 (Ctrl+C 로 종료)
& $py -m fco.refresh quick             # 10단계 빠른 갱신 (보유 매물 + 상위 후보 현재가, 2~4분)
& $py -m fco.refresh daily             # 10단계 일일 갱신 (랭커 스쿼드 + 전체 카드, 40~50분)
powershell -File scripts\register_tasks.ps1     # 작업 스케줄러 등록 (2시간마다 빠른 갱신 + 매일 05:30 일일 갱신)
powershell -File scripts\unregister_tasks.ps1   # 등록 해제
& $py -m unittest discover -s tests -t .       # 날짜 역산·평일주말 계산 테스트
```
`collect_prices` 는 20시간 안에 받은 카드를 건너뛰므로 중단돼도 다시 실행하면 이어서 진행된다.

## 10단계
- **BP 구성 (2026-11-24 수정)**: 총 운용 BP = `cashBp`(보유한 순 BP, 매물 제외) + 보유 매물 현재 평가액. 처음 입력값 8.839억을 883.9억으로 잘못 넣었던 것을 바로잡았다. 순 BP 는 대시보드 설정에서 바꾼다 ("8.839억", "3500만" 같은 입력 가능).
- **내 보유 매물**: 대시보드에서 선수 검색 → 시즌·강화·수량·매수가 입력. 랭커 스쿼드에 없던 카드면 데이터센터 시세를 바로 받아 분석에 포함. 표시: 현재가, 직전 갱신 대비, 평가액, 수수료 차감 평가 손익·ROI, 손익분기 매도가, 예상 매도가와 그때 손익, 판정. 매도 기록 → 실현 손익 누적.
- **자금 배분**: 카드당 한도 = 총 운용 BP × 20% − 그 카드 보유 평가액. 매수는 순 BP 안에서만.
- **추천 검증**: 갱신할 때마다 '지금 매수' 전부 + Deal Score 상위 20장을 하루 1번 기록 → 7일 뒤 일별 가격으로 채점 (지금 매수 = 추천일 현재가, 목표가 대기 = 7일 안에 목표가 도달 시, 매도 = 그 다음 첫 주말 평균, 수수료 차감).
- **자동 갱신**: quick 은 보유 매물 + 활성 가격대 Deal Score 상위 100 + 지금 매수·위험 판정 카드, daily 는 랭커 1~200위 스쿼드(Open API 약 400건) + 전체 카드. 한 번에 하나만 실행(`data/refresh.lock`), 실패해도 기존 데이터 유지, 결과는 `collect_log`·대시보드 '갱신 기록'.
- **분석 기준일은 카드별**: 각 카드의 마지막 일별 가격 날짜. 일부 카드만 갱신돼도 나머지 카드의 지표가 흔들리지 않는다.
- 작업 스케줄러 등록은 `scripts/register_tasks.ps1` (현재 사용자, 로그인 중일 때, 창 없이 `pythonw`). 이 폴더 경로를 가리키므로 폴더를 옮기면 다시 등록해야 한다.

## 9단계 대시보드
- 이 PC 에서만 열린다 (127.0.0.1). 설정 변경은 사용자 지정 헤더가 있어야 받아서 다른 사이트가 바꿀 수 없다.
- 메인: 운용 BP · 분석 카드 수 · 판정별 수 / 자금 배분 / 탭 (Deal Score TOP 20, 평일 매수·주말 매도 후보, 현재 저평가, 가격 안정성 높음, 위험 경고, 전체) / 설정 / 계산식.
- 표 열: 기획서 10장 열 + 목표 매수가·판정·경고. 열 머리를 누르면 정렬, 행을 누르면 상세.
- 상세: 일별 가격 그래프 (30/90/365일, 주말 띠, 평일 평균·적정가·목표가·예상 매도가 점선, 현재가 점, 마우스 올리면 값), 가격·수익, Deal Score 산출 근거, 평일·주말·안정성 지표, 인기 스쿼드 근거, 일별 가격 표.
- 설정 저장 시 4~8단계를 다시 계산한다 (약 4초). 수집은 하지 않는다.
- 자금 배분: 지금 매수 → 목표가 주문(위험 없음 + 최근 30일 일별 가격이 목표가 이하였던 적 있음, 최대 8장) 순, Deal Score 순으로 잔여 BP 에서 차감.
  카드당 최대 수량 5장(`allocation.maxQtyPerCard`)은 기획서에 없는 추가 제한이다 — 거래량을 알 수 없어 한 카드를 수십 장 사고팔 수 있는지 확인할 수 없기 때문. 0 으로 두면 제한 없음.

## 8단계 계산식 (기준값은 settings.json `dealScore`)
- 배점: 인기 30 / 할인 25 / 주말 25 / 안정 20. 현재가 가격대 그룹(1~2억, 2~5억, 5~10억 …) 안 백분위로 정규화.
- 백분위 = 그 값보다 작은 카드 수 / (그룹 카드 수 − 1). 그룹이 30장 미만이면 전체와 비교.
- 데이터 없는 지표는 빼고 남은 배점으로 100점 환산. 데이터 신뢰도 = 사용한 배점 합 (100 높음 / 75 이상 보통 / 그 아래 낮음).
- 위험 감점: 급락 −10, 지속 하락 −15, 당일 급락 −10. 가격 정체 카드는 안정성 지표 제외.
- 경고: 급락·지속하락·당일급락·정체, 기록 부족, 일시적 주말 차이, 인기 순위 급락, 현재가 > 적정가, 예상 ROI < 수수료율.
- 인기 지표만 '그룹 최고 인기 점수 대비 비율'로 정규화 (2026-11-24 결정, `popularityNormalization`). 대부분 0 점이라 백분위로는 1점과 26점이 거의 같아지기 때문. `"percentile"` 로 바꾸면 기획서 원안.

## 7단계 계산식 (기준값은 settings.json `buyPrice`, `fee`)
- 매수 적정가 = 평일 평균 × 할인 계수. 계수는 30일 CV 0.05 이하 → 0.98, 0.30 이상 → 0.90, 사이는 선형.
- 예상 매도가 = 평일 평균 × (1 + 사용 주말 프리미엄). 사용 프리미엄 = max(0, min(공식 프리미엄, 추세 보정 주별 중앙값)), 일시적이면 0.
- 순수익 = 매도가 × (1 − 0.20) − 매수가, ROI = 순수익 / 매수가, 손익분기 매도가 = 매수가 / 0.8.
- 목표 수익률(기본 5%) 최대 매수가 = 예상 매도가 × 0.8 / 1.05. 목표 매수가 = min(매수 적정가, 그 값).
- 판정: buy_now(현재가 ≤ 목표가, 위험 없음) / risky(현재가 ≤ 목표가지만 급락·지속하락·정체·당일급락) / wait / insufficient.
- 도달 가능성: 최근 30일 일별 가격이 목표 매수가 이하였던 날 수 (일별 = 하루 평균이라 장중 최저는 더 낮을 수 있음).

## 6단계 계산식 (기준값은 settings.json `stability`)
- 7일·30일 각각: 기록 일수·기록 비율·최장 공백, 평균, 모표준편차, CV(=표준편차/평균), 변동률(첫날→마지막날), 범위(최고−최저)/평균, 추세(ln 가격 기울기, %/일; ±0.5%/일 안쪽은 보합).
- 급락/급등: 최근 7일 안 전날 대비 −15% / +15% 이상.
- 지속 하락: 30일 변동률 ≤ −10% 이고 30일 추세 하락이고 7일 추세가 상승이 아님.
- 가격 정체: 같은 값이 5일 이상 연속 → 거래 없음 가능성. CV 가 낮아도 안정으로 보지 않는다.

## 5단계 계산식 (기준값은 settings.json `popularSquad`)
- 공식경기 랭킹 1~20위 구단주의 최근 공식경기 스쿼드 사용.
- 순위 가중치 = 21 − 순위 (1위 20점 … 20위 1점). 교체 명단은 × 0.5.
- 카드 점수 = 그 카드를 쓴 스쿼드들의 가중치 합. 출현 횟수(선발/교체)와 순위 목록을 함께 저장. 만점 210점.
- 1~20위가 쓰지 않은 카드는 0점(관측된 값). 1~200위 사용자 수는 참고용으로만 저장.
- 직전 완료 스냅샷 대비 점수가 50% 이상 줄면 급락 경고. 스냅샷이 1개뿐이면 비교 불가로 표시.

## 4단계 계산식 (기준값은 settings.json `weekly`)
- 기준 기간: 가장 최근 일별 가격 날짜 포함 28일. 평일 = 월~금, 주말 = 토·일.
- 평일·주말 각각 평균과 중앙값.
- Weekend Premium = (주말 평균 − 평일 평균) / 평일 평균 × 100 (기획서 공식)
- Discount = (평일 평균 − 현재가) / 평일 평균 × 100
- 반복성: 최근 8번의 주말마다 토·일 평균을 바로 앞·뒤 평일(같은 일수) 평균과 비교 → 추세 영향 제거. 0.5% 넘게 높은 주를 '상승 주'로 센다.
- 공식 프리미엄 > 0 인데 상승 주 비율 < 50% → '일시적' 표시.
- 평일 10일 / 주말 4일 미만이면 '데이터 부족'으로 표시하고 계산하지 않는다.

## 가격 데이터 성질
- 일별 가격은 하루 1개 값(데이터센터 제공, 하루 평균으로 추정). 날짜 라벨에 연도가 없어 마지막 날짜 기준으로 역산하고, 날짜가 이어지지 않으면 `date_check` 에 경고를 남긴다.
- 출시 전 날짜는 데이터센터가 0 으로 주므로 저장하지 않는다 (기록 일수 = 출시 후 일수).
- 현재가는 데이터센터가 2시간마다 갱신한다. 시간대별 기록은 `collect_prices` 를 반복 실행해 `price_current` 에 쌓는다 (자동 실행은 10단계).
- 데이터센터에 시세가 없는 카드(현재가 0)는 `no_data` 로 표시하고 가격을 만들지 않는다.

## 데이터 규칙
- 카드 = (spid, 강화). spid = 클래스 ID × 1,000,000 + 선수 ID. 선수명으로 매칭하지 않는다.
- 강화 0 은 교체 명단의 LIVE 카드에서만 나오는 값이라 카드 마스터에서 제외한다 (원본 스쿼드 기록에는 남긴다).
- 공식 메타데이터에 없는 spid 는 이름을 비워 둔다 (임의로 채우지 않음).
- 수집 실패 시 기존 데이터를 지우지 않는다. 모든 기록에 수집 시각(KST)이 남는다.
- Open API 개발 키 한도: 5건/초, 1,000건/일 → 설정상 4건/초, 900건/일에서 멈춘다.
